# Oversea · AI 原生专业服务总包平台（MVP）

一个可本地运行的出海专业服务总包演示系统：客户创建项目，平台 PM 用 AI 完成需求诊断、项目建议书、服务采购、合同、履约审查、节点验收与归档。

## 技术栈

- 前端：Vue 3 + Vite + Element Plus + ECharts
- 后端：Flask + SQLAlchemy
- 数据库：SQLite（`data/oversea.db`）
- AI：DeepSeek V4.1 Flash（OpenAI 兼容接口，必须配置 API Key）
- 测试：pytest（108 项）

## 快速开始

### 1. 安装后端

```cmd
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

编辑 `backend/.env`，至少填写：

```env
AI_API_KEY=你的 DeepSeek Key
AI_MODEL=服务商控制台中的实际模型 ID
```

未配置 Key 时 AI 接口返回 503，其他页面仍可使用。

### 2. 初始化数据库

```cmd
cd backend
.venv\Scripts\python.exe -m app.seeds.seed --drop
```

`--drop` 会清空并重建所有表，仅用于本地演示。

如果沿用旧数据库，后端启动时会自动补齐模型中新增的列；补齐后执行一次 `python -m app.seeds.seed` 即可补入服务商/专家账号与归属关系。仅当表结构冲突时才需要 `--drop`。

### 3. 启动后端

```cmd
cd backend
.venv\Scripts\waitress-serve.exe --port=5000 wsgi:app
```

### 4. 启动前端

```cmd
cd frontend
npm install
npm run dev
```

访问 http://localhost:5173

## 前端设计

### 角色首页

登录后按角色进入不同页面：

| 角色 | 首页 |
| --- | --- |
| 客户 | `/` 我的项目列表 |
| 项目经理 | `/` 全部项目列表 |
| 复核律师 | `/lawyer` 审批台 |
| 管理员 | `/admin` 控制台 |
| 服务商 | `/provider` 工作台 |
| 验收专家 | `/expert` 工作台 |

PM 进入后先看到项目列表，点击项目卡片进入 `/projects/:projectId` 对话工作台，不再自动打开第一个项目。

### 响应式布局

- **桌面 ≥1201px**：两栏 240px / 自适应；工作台面板为右侧抽屉，点击“工作台”打开。
- **平板 768–1200px**：两栏；工作台面板改为抽屉，点击“工作台”打开。
- **手机 ≤767px**：单栏；左侧项目/会话变为抽屉，点击“菜单”打开；工作台面板全屏；输入框固定底部。
- 项目列表使用 `auto-fill` 卡片网格，手机单列、大屏多列。
- 弹窗宽度使用 `min(94vw, 固定宽度)`，避免手机溢出。
- 问卷在手机上按节分页，选项单列排列。

### 客户建项问卷

客户新建项目分两步：

1. 基本信息：国家、行业、出海方式、投资额、目标。
2. 项目问卷：8 个 part、41 道题，全部以单选/多选/少量文本方式完成。

问卷结果会：

- 保存到 `Project.questionnaire_json`；
- 按 `questionnaire v1.json` 的 32 条规则生成任务范围、追问、风险标记与待上传清单；
- 生成一条“问卷已完成”的欢迎消息，随后进入 AI 问答；
- 作为 AI 对话、访谈、任务地图的上下文。

PM/管理员创建项目可跳过问卷；客户创建必须完成问卷。

### 简洁原则

- 只保留项目、会话、工作台三类核心信息。
- 角色看不到与自己无关的 Tab 和按钮。
- 项目卡片只展示名称、客户、阶段、投资额与状态。
- 不做复杂主题、动画与装饰图形。

## 使用流程

1. **客户登录**，在项目列表点“新建项目”，先填基本信息，再完成 8 节 41 题问卷，创建后进入 AI 问答。
2. 客户可上传资料、与 AI 对话、在“选服务”中勾选服务；在“客户确认”页确认需求、建议书、总报价、合同与节点。
3. **PM 登录**，在项目列表选择项目：提取事实、生成追问、生成任务地图与建议书。
4. PM 推进选服务、候选服务商、RFP、报价、比价与客户总报价。
5. PM 生成合同与节点，客户在“客户确认”中确认，服务商登录 `/provider` 确认。
6. PM 推进交付、答复审查、质询函（律师批准）；服务商登录 `/provider` 回复与提交交付物；专家登录 `/expert` 盲评。
7. PM 汇总验收、生成复盘与归档包；管理员可一键重置演示数据。

完整演示步骤见 `docs/demo-script.md`；当前流程、阶段门禁与代码归属见 `FLOW.md`。

## 当前限制

- 所有角色均有账号并写入数据库；链接仅作为可选协作方式。
- 不做真实电子签名、在线支付、OCR 扫描件、移动端 App。
- AI 依赖 DeepSeek Key 与网络，失败会明确报错，不回退预置数据。
- 本地演示环境，不是生产部署。
