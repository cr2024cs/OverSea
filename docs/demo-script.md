# 10 分钟演示脚本

## 0. 演示前

```cmd
cd backend
.venv\Scripts\activate
.venv\Scripts\python.exe -m app.seeds.seed --drop
.venv\Scripts\waitress-serve.exe --port=5000 wsgi:app
```

```cmd
cd frontend
npm run dev
```

- 浏览器：http://localhost:5173
- 客户：`client@demo.local / demo1234`
- PM：`pm@demo.local / demo1234`
- 律师：`lawyer@demo.local / demo1234`
- 管理员：`admin@demo.local / demo1234`
- 服务商：`provider@demo.local / demo1234`（登录 `/provider`）
- 验收专家：`expert@demo.local / demo1234`（登录 `/expert`）
- 必须配置 `backend/.env` 的 `AI_API_KEY`；未配置时 AI 接口返回 503。
- 演示前确认网络可访问 DeepSeek API。
- 项目列表中有两个演示项目：进行中的“泰国春武里汽车零部件工厂”和已归档的“泰国春武里汽车零部件工厂（完结版）”。后者阶段 7、全部交付物已完成，可直接打开工作台逐阶段查看已完成的建议书、报价、合同、节点、审查、复盘与归档包。

## 1. 客户创建项目与诊断（0:00–2:00）

1. 客户登录 `client@demo.local`，列表中可见自己名下的“泰国春武里汽车零部件工厂”。
2. 点“新建项目”，填写基本信息（国家、行业、出海方式、投资额、目标）。
3. 进入项目问卷：8 节 41 题，按单选项/多选项完成；展示条件题随答案出现或隐藏。
4. 提交后进入项目，看到“问卷已完成”摘要与待追问项，然后开始 AI 问答。
5. 客户可上传一份 txt/docx，与 AI 对话。
6. 切换 PM 登录，进入同一演示项目。
7. 中栏发送：“我们计划在泰国东部经济走廊设厂，投资约 3000 万美元，其中 800 万美元设备出资，目标 14 个月试产。”
8. 展示流式回复与“草稿”标签。
9. 打开右侧“事实” → 提取事实：5 条，来源可点击跳原文高亮。
10. 生成追问：最多 5 个，按影响任务排序。
11. 打开“任务” → 切换“园区外买地”：关键路径变长，差异提示出现。

## 2. 需求确认（2:00–2:40）

1. PM 在“需求”页生成需求确认书。
2. 切换客户账号，打开“客户确认”页 → 确认需求。
3. 回到 PM，确认时间已记录。

## 3. 项目建议书（2:40–4:00）

1. PM 在“建议书”页生成建议书：8 章、预算低/中/高。
2. 展示 RAG 引用 chip 与“非正式报价”声明。
3. PM 审核 → 发送。
4. 切换客户账号，在“客户确认”页先点“提出修改”，填写“补充预算假设”。
5. 回 PM 重新生成 v2 → 审核 → 发送。
6. 客户在“客户确认”页确认建议书（进入阶段 3）。

## 4. 选服务与询价（4:00–6:00）

1. 客户在“选服务”页勾选 T11（BOI 申请与取证）并保存；PM 可代选但需填原因。
2. PM 在“服务商”页生成候选：每任务 5 家，展示评分、证据、内部库/新发现。
3. PM 在“报价”页生成询价书 → 批准 → 发送。
4. 切换服务商账号登录 `/provider`，在待报价询价书中粘贴“报价合计 50 万元人民币”提交。
5. PM 回报价页：比价表显示最低价与价差。
6. PM 生成总报价：服务商 40 万、律所 0、管理费 17.5% → 47 万 → 发送。
7. 客户在“客户确认”页确认总报价。

## 5. 合同与节点（6:00–7:00）

1. PM 在“合同”页生成合同与节点，并完成 PM 复核。
2. 客户在“客户确认”页确认合同。
3. 服务商登录 `/provider`，在“服务商委托合同”中确认委托。
4. 合同变为“已生效”，项目进入执行中。
5. 展示文件哈希与 SLA。

## 6. 履约与审查（7:00–9:00）

1. PM 在“节点”页提交交付物（演示）→ 初审通过。
2. 点“审查答复”：生成审查发现（约 7–8 条，取决于真实模型输出）。
3. 打开“审查”页：三栏展示原文高亮、发现列表、追问详情。
4. 生成质询函 → 切律师账号 → 批准质询函。
5. PM 发送质询函；服务商登录 `/provider` 逐条回复。
6. PM 关闭质询。

## 7. 专家验收与归档（9:00–10:00）

1. PM 在节点页“邀请专家”，默认分配给 `expert@demo.local`。
2. 专家登录 `/expert`，填写四维评分与意见，勾选无利益冲突 → 提交锁定。
3. PM“汇总验收”：通过，依赖任务解锁（T12、T20）。
4. 客户在“客户确认”页确认节点。
5. PM 在“归档”页：生成复盘 → 查看三项指标与报价基准 → 生成归档包 → 下载 zip。 
6. 展示归档后只读与 `manifest.json`。
7. 用管理员登录 → “归档”页“一键重置演示”。

## 8. 一页备忘

- 演示主线：诊断 → 建议书 → 选服务 → 询价报价 → 合同 → 审查验收 → 归档。
- 三个必须展示的拦截：
  1. 法律类质询未律师批准不能发送。
  2. 节点未通过不解锁依赖任务。
  3. 归档后写接口 409。
- 兜底：AI 调用失败时界面会显示明确错误；检查 Key 与网络后重试；演示异常时执行
  `python -m app.seeds.seed --reset-demo`。
