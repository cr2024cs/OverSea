# UI 规范（MVP）

## 1. 布局

主界面为两栏对话工作台，工作台在对话区以抽屉弹层显示：

```text
┌──────────┬────────────────────────────────────────────┐
│ 项目/会话 │ 项目名 + 七阶段步骤条                        │
│ 220-260px│ 消息流 / 输入框                             │
└──────────┴────────────────────────────────────────────┘
                        工作台面板（抽屉弹层，约 420px，可展开全屏）
```

- 左栏：项目列表、当前项目会话、新建对话、用户信息与退出。
- 右栏（主区）：项目名、状态、七阶段步骤条、消息流、快捷指令、输入框、附件上传。
- 工作台面板：默认不占列，点击“工作台”在对话区右侧以抽屉弹层打开，带遮罩；顶部以七个阶段作为主导航，阶段内在子 Tab 中查看内容，未到达阶段置灰不可点。所有角色的抽屉都尽量占满屏幕（桌面 `min(1400px, 96vw)`，手机 100vw）。
- 全屏：面板“展开”后固定为全屏浮层，适合任务图与三栏审查。

### 1.1 角色首页

| 角色 | 首页 | 内容 |
| --- | --- | --- |
| 客户 | `/` | 自己的项目列表、新建项目 |
| PM | `/` | 全部项目列表，点击进入对话工作台 |
| 律师 | `/lawyer` | 待审批质询、项目入口 |
| 管理员 | `/admin` | 账号、计数、审计、指标导出、重置 |
| 服务商 | `/provider` | 询价、报价、合同、交付、质询 |
| 专家 | `/expert` | 分配节点与盲评 |

### 1.2 响应式

- 桌面 ≥1201px：两栏对话 + 工作台抽屉弹层。
- 平板 768–1200px：两栏对话 + 工作台抽屉弹层。
- 手机 ≤767px：单栏，项目/会话抽屉 + 工作台全屏抽屉。
- 项目列表 `auto-fill` 卡片：手机单列、大屏多列。
- 弹窗宽度 `min(94vw, 固定宽度)`。
- 客户建项问卷按节分页，手机选项单列；条件题实时显示/隐藏。

### 1.3 客户建项问卷

新建项目分两步：基本信息 → 8 节 41 题问卷。问卷全部通过单选项/多选项完成，仅 Q41 为文本补充。提交后创建项目、生成任务范围，并进入 AI 问答。

| 项 | 值 |

不使用渐变背景、装饰插图、重阴影与多强调色。

## 3. 消息与 AI 状态

- 用户消息右对齐浅灰气泡；AI 消息左对齐、头像 + Markdown。
- AI 流式输出显示光标；界面不显示模型名。
- AI 失败时展示明确错误，不回退到预置数据。
- AI 生成内容统一通过“待审核 / 待确认”业务状态和人工确认按钮管理，不在每条消息上显示技术性“草稿”标签。
- 所有 AI 结果需要 PM 确认后才能作为下一步输入。
- 引用 chip 点击打开原文并高亮字符区间。
- 对话区顶部显示“下一步”引导条：按阶段给出“生成任务地图 / 生成需求确认书 / 生成项目建议书”等明确动作。
- 对话本身不会自动推进阶段；阶段由引导条或右侧业务动作触发。

## 4. 工作台面板

工作台顶部为七个阶段主导航（调研/建议/询价/报价/签约/履约/归档），点击阶段后在阶段内子 Tab 查看交付内容；项目尚未到达的阶段置灰且不可点击。客户确认作为独立常驻入口（阶段编号位显示“确认”）。

| 阶段 | 子 Tab | 内容 | 主要操作 |
| --- | --- | --- | --- |
| 调研 | 事实 | 事实、状态、来源引用、追问清单 | 提取事实、生成追问 |
| 调研 | 任务 | ECharts 依赖图、关键路径、任务列表、版本差异 | 租厂房/园区外买地、刷新 |
| 调研 | 需求 | 需求确认书 | 生成、打印、客户链接 |
| 建议 | 建议书 | 8 章、预算、RAG 引用、版本 | 生成、审核、发送、客户链接、对比、打印 |
| 询价 | 选服务 | 按阶段勾选、依赖提示 | 保存、客户选择链接 |
| 询价 | 服务商 | 候选卡片、评分、证据、来源 | 生成候选、标记不合适 |
| 报价 | 报价 | RFP、批准发送、比价、总报价编辑器 | 生成询价、发送、客户链接 |
| 签约 | 合同 | 条款、节点、服务商委托单、哈希 | 生成、复核、客户/服务商链接、打印 |
| 履约 | 节点 | 看板、逾期提醒、催办、初审、专家、验收 | 提交、初审、审查、邀请专家、汇总、整改 |
| 履约 | 发现 | 七类检查结果与详情 | 查看引用与追问 |
| 履约 | 审查 | 三栏：原文/发现/详情、质询函 | 运行审查、生成质询函、批准/发送/关闭 |
| 归档 | 归档 | 指标、复盘、报价基准、归档包 | 生成复盘、生成归档、下载、一键重置 |
| 确认（常驻） | 客户确认 | 客户待确认的需求/建议书/报价/合同/节点 | 客户账号内直接确认 |

## 5. 公开链接页

| 页面 | 角色 | 能力 |
| --- | --- | --- |
| `/link/:token` | 客户 | 需求确认 |
| `/proposal-link/:token` | 客户 | 建议书确认/修改 |
| `/selection-link/:token` | 客户 | 服务选择 |
| `/rfp-link/:token` | 服务商 | 查看 RFP、提交报价 |
| `/client-quote-link/:token` | 客户 | 总报价确认 |
| `/contract-link/:token` | 客户/服务商 | 合同与节点确认 |
| `/expert-link/:token` | 验收专家 | 盲评打分（无服务商与报价） |
| `/query-link/:token` | 服务商 | 逐条回复质询 |

公开页为单栏文档式布局，最大宽度 640–900px，无内部导航。

服务商与专家使用独立账号工作台：`/provider`、`/expert`，不进入客户/PM 的三栏对话界面。

## 6. 状态与反馈

- 加载：显示“正在加载…”，不显示空白。
- 空态：说明缺少什么、下一步点哪里。
- 错误：展示后端 `message`，不暴露堆栈。
- 操作成功：顶部轻提示（Element Plus Message）。
- 危险操作：二次确认（归档生成、一键重置）。
- 归档后：面板显示“只读”，写操作返回 409。

## 7. 打印

- 从工作台面板打印时隐藏侧栏、消息流、输入框与面板 Tab。
- 只保留当前工作台内容。
- 合同、建议书、报价与需求确认书必须包含边界声明。
- 专家评分页不显示服务商、报价与内部备注。

## 8. 1366×768 适配

- 两栏布局：左栏 240、对话自适应；工作台抽屉弹层约 420，正文最小宽度约 700。
- 面板 Tab 横向滚动，不换行挤压。
- 审查三栏在窄屏自动堆叠为单列；展开面板后恢复三栏。
- 所有表格与卡片不出现横向滚动条。

## 9. 已知限制

- 移动端未适配。
- 不支持深色模式。
- 图表允许拖拽缩放，但不支持节点编辑。
- 文件上传仅支持 txt/md/docx/文本型 PDF。
